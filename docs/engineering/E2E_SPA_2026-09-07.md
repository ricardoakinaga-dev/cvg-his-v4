# Evidência E2E SPA — 2026-09-07

## Resultado

O recorte E2E browser-to-database foi executado contra PostgreSQL e Redis reais
locais, com API e SPA construídas, sem fallback de memória. O resultado foi
`PASS_BOUNDED`: **9/9 testes passaram**, com exit 0.

Na mesma revalidação técnica, a matriz visual passou **29/29 casos** em páginas
de lista, detalhe, agenda, balcão, tema claro/escuro e mobile. A auditoria
master de usabilidade passou **299/299 casos** (149 rotas em dois viewports e o
gate agregado), usando uma página nova por rota para impedir acúmulo de recursos
do renderer. Os dois resultados são `PASS_BOUNDED` locais: não substituem UAT,
WCAG independente, browser adicional ou homologação no target.

| Grupo                       | Cobertura executada                                                               | Resultado |
| --------------------------- | --------------------------------------------------------------------------------- | --------- |
| Personas hospitalares       | recepção, veterinário clínico, patologista, ultrassonografista e administrador    | 5/5       |
| Busca Mestre 360 / recepção | paciente prioritário, exames pendentes, preventivo vencido e pendência financeira | 4/4       |
| **Total**                   | **9 jornadas browser com persistência**                                           | **9/9**   |

| Matriz visual SPA | páginas, detalhes, agenda, comanda, light/dark e mobile | 29/29 |
| Auditoria master de usabilidade | 149 rotas × 2 viewports + gate agregado | 299/299 |
| Lote crítico, acessibilidade e enterprise | RBAC, internação, agenda, billing, axe, responsividade, relatórios e finanças | 40/40 |
| Lote D de integração e UX | NFS-e, setup, isolamento tenant, Vetus, webhooks e matriz visual completa | 40/40 |

## Envelope reproduzido

- migrations canônicas `0000–0164`, incluindo a correção incremental
  `0164_allow_billing_item_cascade_delete.sql`;
- API com `persistenceMode=database`, `productionReady=true` e repositórios
  críticos persistentes;
- Redis real para o rate limiter distribuído;
- autenticação, autorização, tenant, agenda, esteira, prontuário, prescrição,
  laboratório, laudo, busca 360 e limpeza de dados de teste;
- cleanup sem falha: encounters, pacientes e tutores criados pelo recorte
  foram removidos; as cinco bases efêmeras usadas nos ensaios foram verificadas
  sem conexões ativas e descartadas ao final.
- a captura de login oculta somente o vídeo decorativo e usa o poster estático,
  eliminando flutuação de frame sem relaxar o limiar de pixels;
- a agenda visual usa a query pública `agendaDate`/`agendaView=day`, em vez de
  depender do mini-calendário recolhido;
- a auditoria master abre uma página nova por rota e preserva o gate de 149
  rotas em cada viewport.

As respostas `401`, `403` e o `404` de ausência de comanda observados nos logs
foram negativas esperadas de autenticação/autorização ou pré-carregamento sem
registro; não produziram falha de teste nem erro de cleanup. Elas permanecem
úteis para a revisão de ruído operacional e severidade de logs.

## Reprodução

O recorte foi executado pelo runner oficial com `E2E_DATABASE_URL` apontando
para uma base PostgreSQL efêmera e `E2E_REDIS_URL=redis://127.0.0.1:6381`:

```text
E2E_PLAYWRIGHT_TARGET="e2e/spa/hospital-personas-routines.spec.ts e2e/spa/master-search-360-reception.spec.ts" \
  bash infra/scripts/run-e2e-spa.sh
```

O banco e o Redis foram encerrados depois da execução; nenhum banco com prefixo
`cvg_his_v2_e2e_` ou `cvg_his_v2_test_critical_` permaneceu no cluster local.

## Limites e promoção honesta

Esta evidência melhora `AAA-013` para `REVIEW` no escopo local, mas não o fecha
como `DONE`. Ainda faltam:

1. checkout limpo, SHA/digest imutável e repetição no CI remoto;
2. matriz completa de browser, loading/empty/error/retry, teclado, foco, leitor
   de tela e WCAG 2.2 AA com revisão independente; a matriz visual local acima
   não substitui esses controles;
3. internação/alta, ciclo financeiro completo, providers reais, paridade Vetus,
   target operacional, carga, restore e aceite humano;
4. recertificação conforme a regra de três rodadas e 20 repetições sem flake.
