# PLANO DE ACAO 30-60-90 DIAS - CVG-HIS-V2

## Objetivo

Transformar a matriz de aderencia enterprise em um plano de execucao curto, priorizado e utilizavel em gestao.

Este plano assume tres principios:

- proteger a fundacao tecnica antes de acelerar novas frentes
- fechar Onda 1 residual e consolidar Onda 2 antes de escalar Onda 3
- adiar AI/ML e certificacao formal ate haver maturidade de dados, eventos e operacao

## Papeis sugeridos

| Sigla  | Papel                 | Responsabilidade principal                              |
| ------ | --------------------- | ------------------------------------------------------- |
| `TL`   | Tech Lead / Arquiteto | Sequenciamento tecnico, trade-offs, criterios de aceite |
| `BE`   | Backend Lead          | API, auth, tenancy, observabilidade, integracoes        |
| `FE`   | Frontend Lead         | SPA, design system, UX premium, adocao de componentes   |
| `PLAT` | Platform / DevOps     | CI, ambientes, monitoramento, performance e release     |
| `SEC`  | Security / Compliance | MFA, hardening, LGPD operacional, trilha de auditoria   |
| `QA`   | QA / Automation       | gates, suites E2E, regressao visual, quality score      |
| `PO`   | Product / Operations  | corte de escopo, ordem de valor, aceite por onda        |

## Ordem de execucao

1. estabilizar fundamentos que bloqueiam release confiavel
2. consolidar frontend e padroes de UI para reduzir regressao
3. abrir trilha minima de Onda 3 com API premium e integracoes de maior retorno
4. preparar base para performance e documentacao operacional
5. postergar AI/ML e certificacao formal para uma fase de dados mais madura

## Plano 30 dias

### Meta do periodo

Fechar os principais riscos de fundacao e deixar o produto apto para uma cadencia mais confiavel de entrega.

| -------------------------------------------------- | ------------------------------------------------------------------------ | -------------------- | ------------- | ---------- |

| Fechar hardening de autenticacao mais critico      | Regras minimas de brute force, bloqueio e controles de sessao            | `BE` + `SEC`         | Rate limiting | Alta       |
| Mapear gap final de MFA                            | Lista objetiva do que falta entre TOTP atual e alvo enterprise           | `SEC` + `BE`         | Nenhuma       | Alta       |
| Consolidar LGPD minimo operacional                 | Consentimento, DSR e export com fluxo validado e criterios de uso        | `SEC` + `BE` + `PO`  | Nenhuma       | Alta       |
| Formalizar baseline de observabilidade             | Dashboard minimo, alertas base e padrao de correlação/log                | `PLAT` + `BE`        | Nenhuma       | Alta       |
| Remover ambiguidade de release na CI               | Tornar falhas de teste/coverage visiveis e impeditivas quando necessario | `PLAT` + `QA` + `TL` | Nenhuma       | Alta       |
| Revisar gaps estruturais dos relatorios internos   | Fechar ou reclassificar gaps de persistencia, RBAC e readiness           | `TL` + `BE` + `QA`   | Nenhuma       | Alta       |

- rate limiting habilitado e validado
- checklist de hardening de auth em producao assistida

- scorecard operacional atualizado semanalmente
- backlog de adocao de design system priorizado
