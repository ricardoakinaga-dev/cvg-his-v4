## 🔄 Como Integrar

### 1. Rodar Migration
```bash
cd packages/db
npm run migrate
```

### 2. Integrar Worker no his-worker
Adicionar no `apps/his-worker/src/index.ts`:

```typescript
import { createNotificationWorker } from './workers/notification.worker.js';
import { createNotificationProcessQueue, NOTIFICATION_QUEUE_NAME } from './queues/notification.queue.js';

// No bootstrap():
const notificationWorker = createNotificationWorker(redis, env.QUEUE_PREFIX);
const notificationProcessQueue = createNotificationProcessQueue(redis, env.QUEUE_PREFIX);

// Registrar logs
notificationWorker.on('ready', () => {
  logInfo('notification worker ready', { queue: NOTIFICATION_QUEUE_NAME });
});

// Adicionar cron para processar fila a cada 60s
const notificationCron = startCron({
  name: 'notification-process-queue',
  intervalMs: 60000,
  runOnStart: true,
  onTick: async () => {
    await notificationProcessQueue.add('notification:process-queue', {
      trigger: 'scheduled',
      enqueuedAt: new Date().toISOString()
    });
  }
});

// No shutdown():
await notificationWorker.close();
await notificationProcessQueue.close();
notificationCron?.stop();
```

### 3. Registrar Rotas na API
Adicionar no `apps/his-api/src/routes/index.ts`:

```typescript
import { notificationRoutes } from '../modules/notifications/routes.js';

// No register():
await app.register(notificationRoutes);
```

### 4. Executar Testes
```bash
# Testes do backend
cd apps/his-api
npm test -- --testPathPattern=notifications

# Testes do worker
cd apps/his-worker
npm test -- --testPathPattern=notification
```

## 📝 Notas

1. **Provedores**: As implementações de provedores estão como placeholders. É necessário implementar as chamadas reais para Twilio, Zenvia, SendGrid e Mailgun.

2. **Worker**: O worker pode ser usado de duas formas:
   - **Com BullMQ**: Integrado no his-worker para processamento assíncrono
   - **Standalone**: Usando o worker.ts diretamente para processamento síncrono

3. **Templates**: Templates padrão são criados automaticamente quando uma nova conta é adicionada.

4. **Horário de Silêncio**: Notificações agendadas durante o horário de silêncio são automaticamente reagendadas para após o período.

5. **Retry**: Notificações falhadas são automaticamente reenviadas até 3 vezes com intervalo configurável.
